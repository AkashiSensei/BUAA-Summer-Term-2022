# 原开发文档

以下文字从 2022 年提交版开发文档提取，仅整理标题和段落，保留当时的叙述与认识；部分技术解释反映的是初学阶段的理解。当前启动方法以仓库 README 为准。

## 1. 创意来源
在玩耍空洞骑士游戏的时候，我十分喜欢该游戏的音乐、美术以及剧情设计，于是便借鉴该游戏原型版本——饥饿骑士，开发2维平面打怪升级小游戏。
在空洞骑士游戏中，玩家死亡时会在原地留有灵魂，而在本游戏中，将灵魂设计为游戏角色的技能，可以用来躲避物理伤害，造成高额伤害，以及走出地图完成解密。
## 2. 实现思路
使用空洞骑士拆包图片，利用Photoshop进行个性化修改，用作游戏视觉素材。使用Java Swing完成游戏图形界面的开发。
通过游戏启动时首先启动的开始界面，对游戏窗口大小，刷新率以及游戏难度进行设置。在设置完成后，开始界面窗口充当启动器，初始化游戏状态，并启动游戏主窗口。
主窗口启动后，读取Status类中的游戏状态信息，并据此初始化并显示窗口。在窗口启动完成后，进行游戏人物的初始化，完成后，使用部分人物角色数据，进行MyMap地图类的初始化，在此过程中，所有的地图素材都会被读入。之后，进行新手指导器以及怪物类Monster的初始化，同样的，在该初始化过程中也会读入所有的图片素材。初始化完成后，将各个Swing组件加入窗口。
窗口初始化完成后，依据地图进入方式设置人物出生位置，并在该地图上生成相应怪物。人物的移动主要通过地图的移动来显示，默认情况下，人物会显示在屏幕正中，地图的显示位置依据人物在地图中的位置相应改变，而怪物的位置则是读取地图位置进行相应显示。
游戏通过一个持续运行的刷新器，实现每帧的显示，通过改变刷新器的延时来改变帧率。在刷新器中，进行角色图标、地图显示位置、怪物显示位置的变换，同时进行地图边界以及怪物碰撞的判断。如果有碰撞，则将伤害数据、击退数据等传给人物角色LittleKnight类进行处理。
地图中设有传送门，可以在多个地图之间切换。通过不同方式进入的地图，会出生在不同位置，使用地图类中一方法，根据不同进入方式，实现游戏角色位置的变换。
攻击时，人物角色LittleKnight类会将攻击判定框传送给Monster怪物类，在怪物类中计算是否能够攻击到怪物，如果能够攻击到，调用underAttack方法进行处理。

## 4. 技术细节
(1)通过使用drawImage方法，每帧重绘，进行帧刷新的话，运行时间长了之后资源占用较高，效率下降，会出现闪屏问题，需要使用双缓冲技术，先将每帧内容写入图片，再将其写入屏幕。但我没有使用这种方案，而是通过Swing，在窗口添加诸多JLabel实现各个内容的显示，每帧通过调用setLocation方法实现显示位置的变化，通过调用setIcon方法切换不同状态的图片；
(2)怪物和角色类中均有underAttack方法，通过该方法处理造成的伤害以及击退；
(3)MyMap地图类以及Monster怪物类均为抽象类，通过编写他们的实现类来添加地图以及怪物种类的增加。在子类中可以修改各个怪物的生命值、攻击力、被击退距离、移动速度、巡逻范围等数据，并且Monster类中定义类抽象方法，通过在实现类中实现各抽象方法，来赋予不同怪物不同的死亡效果等，如掉落钱币，死亡造成伤害等等。
(4)在Monster类中的stroll方法，为每一个新出生的怪物添加一个线程，用于处理怪物的闲逛逻辑，每个怪物的速度和单次行走的长度均不相同。怪物不会自己走出地图。该方法内部还对怪物状态进行判断，对处于对玩家的仇恨之中的怪物、攻击逻辑中的怪物以及死亡的怪物没有改变其坐标的权限。该类中也有判断怪物仇恨的方法，通过与玩家间的距离控制怪物仇恨玩家与否，若进入仇恨状态，直到仇恨解除或死亡，怪物都会主动攻击玩家，目前由于时间因素，并没有具有主动攻击逻辑的怪物。
(5)怪物的图标会在游戏中发生改变，而这主要由四个控制器控制，分别是移动图标控制器，受伤图标控制器，攻击图标控制器以及灵魂状态图标控制器控制（死亡图标控制未包含在此列）。其中灵魂状态图标控制器独立与其他三者，用于在小骑士进入灵魂状态时切换另一套显示图标。具体的实现方法是，另外三个主要控制器会读取闲逛图标以及攻击图标这两个三维数组，依照怪物行进方向、是否受到攻击，以及怪物攻击方向，和攻击图片帧数选择出一个代表当前状态的一维图标数组传送给灵魂状态图标控制器，由该控制器判断选用普通状态图标，还是灵魂状态图标；
(6)为了便于统一管理，各个元素在屏幕上的显示位置使用逐级继承的方式。首先通过摄像机视角偏移计算出游戏角色的显示位置（默认屏幕正中），再利用游戏角色的显示位置以及角色相对于地图的位置计算地图显示位置，再利用地图显示位置以及怪物相对于地图的位置计算怪物显示位置；
(7)通过游戏状态管理各个监视器效应器等的行为，例如移动等命令只在游戏进行中起效，在游戏暂停时以及玩家死亡时等均不可用，而新手教程则在游戏中以及死亡后复活前均可使用；
(8)地图类中通过地图就绪方法ready实现地图的准备，当需要进入一张新的地图时，该方法根据进入代码的不同而选择合适的出生位置，是出生在椅子上、前传送门抑或是后传送门。
## 5. 收获
(1)从零开始学习Java，并取得了一定的成果，能够较为熟练的使用Java的包、类、接口等组件，类、接口、抽象方法等的继承与实现，对由static、 final等关键字以及private等权限修饰关键字修饰的变量或常量等有了一定的认识，并且能够较为熟练地使用Intellij IDEA编辑Java项目；
(2)开发过程中遇到并解决了各种细节问题，锻炼了解决问题的能力，同时也积累了学习一门新的编程语言的思路与方法；
(3) 多次重构了代码的组织方式，优化了其结构，使其便于阅读、开发、扩展和维护，对类与类之间的沟通以及面向对象编程有了初步了解；
(4)类的构造方式上尝试向标准JavaBean类靠拢，将内部变量均设为private访问权限，并通过getter和setter进行访问，为之后的深入学习打下基础。
